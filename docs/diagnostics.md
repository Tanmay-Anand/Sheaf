# Diagnostic Taxonomy — v1.2

Every way a plan can fail type-checking, with structured error codes, the step context each applies to, and the repair hint surfaced to the LLM (not the user). Written while the type rules are fresh — retrofitting good diagnostics never happens.

**Format:**
- `code` — machine-readable identifier; prefix `E_` for errors, `W_` for warnings.
- `step` — the step index (0-based) at which the error occurs, or `null` for plan-level errors.
- `message` — human-readable description (shown to the user in the refusal message).
- `hint` — repair signal sent back to the model in the repair loop. Specific and actionable.
- `operator` — the step's operator (`aggregate`, `dropColumn`, `sink`…).
- `pointer` *(v1.2, replaces `field`)* — an RFC 6901 JSON Pointer from the plan's root to the offending field: `/steps/2/measures/0/of`, `/ops/1/position/column`, `/sink/templateId`. For commit-time diagnostics it points into the commit request (`/onDependents`, `/anchor/address`). Parse errors point at the field as written; `""` is the whole document.
- `context` — structured detail: `received`, closest match (`suggestion`), `expected` and `actual`, dependents, and for every unknown name up to five `candidates`, closest first (by edit distance, ignoring case).

**Implementation:** `service/src/main/java/com/sheaf/domain/validation/`. The enum `DiagnosticCode` is the authoritative list, and every error code is exercised by `service/src/test/resources/invalid-plans.json` (generated by `corpus/tools/generate_plans.py`) or a targeted test (`TypeCheckerTest`, `BinderTest`, `ConsentCheckTest`).

**Where each is raised (v1.2):** parse errors by `PlanParser`; `E_UNKNOWN_SOURCE` and `E_TEMPLATE_UNKNOWN` by the `Binder`; the rest of the `E_` codes by the type checker; the *Commit* codes by `ConsentCheck`, against the user's commit request. The examples below show `expected`/`actual` at the top level for readability; in the implementation they sit inside `context`.

## Plan-level errors

### `E_UNKNOWN_SOURCE`

```json
{
  "code":    "E_UNKNOWN_SOURCE",
  "step":    null,
  "pointer": "/source",
  "message": "'Order' is not a known table. Did you mean 'Orders'?",
  "hint":    "Known tables: Budget, Contacts, Inventory, Orders, Regions, Tasks.",
  "context": { "received": "Order", "candidates": ["Orders", "Regions"] }
}
```

**When:** `source` (or an edit's `target`) matches no catalog entity, ignoring case. Raised while binding.

---

### `E_SINK_NEW_SHEET_NAME_MISSING`

```json
{
  "code":    "E_SINK_NEW_SHEET_NAME_MISSING",
  "step":    null,
  "message": "A newSheet sink requires a name for the new sheet.",
  "hint":    "Add a 'name' field to the sink, e.g. { \"mode\": \"newSheet\", \"name\": \"Analysis\", \"anchor\": \"A1\" }."
}
```

**When:** a bound `newSheet` sink has no name. The binder always supplies one (a model's intent may omit it), so this only happens to a hand-built or stored plan.

---

### `E_SINK_SHEET_NAME_INVALID` / `E_SINK_SHEET_NAME_TAKEN` *(v1.2)*

**When:** a bound `newSheet` name isn't a valid Excel sheet name (over 31 characters; contains `[ ] : * ? / \`; starts or ends with `'`; is `History`), or a sheet with that name already exists, ignoring case. The binder sanitises and de-duplicates the model's suggestion, so as with the previous code these guard stored plans.

---

### `E_SINK_ANCHOR_INVALID`

```json
{
  "code":    "E_SINK_ANCHOR_INVALID",
  "step":    null,
  "message": "Sink anchor 'Z999' is not a valid cell reference.",
  "hint":    "Use a standard A1-notation cell reference, e.g. \"A1\"."
}
```

**When:** a `newSheet` anchor, or the commit request's `anchor.address` for an `anchor` sink, is not a single A1 cell (`B2`, `$B$2`; not `B2:C9`).

---

### `E_EMPTY_PIPELINE_WRITE`

```json
{
  "code":    "E_EMPTY_PIPELINE_WRITE",
  "step":    null,
  "message": "A plan with no steps writes the entire source entity to the sink. Confirm this is intended.",
  "hint":    "If you meant to filter or transform the data, add at least one step. If you genuinely want to write the full entity, this plan is valid — the user will see the full row count in the preview."
}
```

**When:** `steps` is empty and `sink.mode` is `"anchor"`. Treated as an error because overwriting an existing range with all rows is almost certainly unintentional.

## Column reference errors

### `E_UNKNOWN_COLUMN`

```json
{
  "code":     "E_UNKNOWN_COLUMN",
  "step":     2,
  "operator": "aggregate",
  "message":  "Column 'amt' does not exist. Did you mean 'amount'?",
  "hint":     "Available columns at this step: order_id (string), order_date (date), region (categorical), channel (categorical), product_category (categorical), product_name (string), quantity (number), unit_price (currency:INR), amount (currency:INR), discount_pct (percent), status (categorical), customer_type (categorical).",
  "context":  { "received": "amt", "available": ["order_id", "order_date", "region", "channel", "product_category", "product_name", "quantity", "unit_price", "amount", "discount_pct", "status", "customer_type"] }
}
```

**When:** any operator references a column name that does not exist in the current table type at that step.

**Hint strategy:** include the full list of available columns at the failing step, and a nearest-neighbour suggestion (edit distance ≤ 2) when available.

---

### `E_COLUMN_NOT_IN_OUTPUT`

```json
{
  "code":     "E_COLUMN_NOT_IN_OUTPUT",
  "step":     3,
  "operator": "sort",
  "message":  "Column 'order_date' was removed by the preceding aggregate step and cannot be referenced here.",
  "hint":     "After aggregating, only groupBy columns and declared measures remain. Available columns after the aggregate: region (categorical), revenue (currency:INR).",
  "context":  { "received": "order_date", "removedBy": 2 }
}
```

**When:** a step references a column that existed in a prior step but was eliminated by an intervening operator (most commonly: referencing a pre-aggregate column after an `aggregate` step).

---

### `E_DERIVE_COLUMN_COLLISION`

```json
{
  "code":     "E_DERIVE_COLUMN_COLLISION",
  "step":     1,
  "operator": "derive",
  "message":  "Column name 'amount' already exists. Derived columns must have unique names.",
  "hint":     "Choose a different name for the derived column, e.g. 'adjusted_amount' or 'net_amount'.",
  "context":  { "received": "amount", "existingColumns": ["order_id", "order_date", "region", "channel", "product_category", "product_name", "quantity", "unit_price", "amount", "discount_pct", "status", "customer_type"] }
}
```

**When:** `derive.as` is the same as an existing column name in the current table type.

## Type mismatch errors

### `E_TYPE_MISMATCH`

```json
{
  "code":     "E_TYPE_MISMATCH",
  "step":     2,
  "operator": "aggregate",
  "pointer":  "/steps/2/measures/0",
  "message":  "sum expects a numeric column (number, currency, or percent), but 'region' is categorical.",
  "hint":     "sum requires a numeric column. Available numeric columns at this step: quantity (number), unit_price (currency:INR), amount (currency:INR), discount_pct (percent).",
  "context":  {
    "fn":       "sum",
    "of":       "region",
    "expected": "number | currency:* | percent",
    "actual":   "categorical(region)"
  }
}
```

**When:** an aggregate function receives a column whose type does not satisfy the function's input constraint.

---

### `E_TYPE_INCOMPARABLE`

```json
{
  "code":     "E_TYPE_INCOMPARABLE",
  "step":     0,
  "operator": "filter",
  "message":  "Cannot compare 'amount' (currency:INR) to 'status' (categorical). These types are not comparable.",
  "hint":     "Compare currency columns only to other currency:INR values or numeric literals. Compare categorical columns to string literals or other categorical columns with the same domain.",
  "context":  {
    "left":  { "col": "amount", "type": "currency:INR" },
    "right": { "col": "status", "type": "categorical" }
  }
}
```

**When:** a predicate or arithmetic expression compares two operands of incompatible types.

---

### `E_CURRENCY_UNIT_MISMATCH`

```json
{
  "code":     "E_CURRENCY_UNIT_MISMATCH",
  "step":     3,
  "operator": "derive",
  "message":  "Cannot add currency:INR and currency:USD. Currency units must match.",
  "hint":     "Both operands must have the same currency unit. The 'amount' column is currency:INR. If you need to convert, apply a conversion factor using mul() before adding.",
  "context":  {
    "left":  { "col": "amount",    "type": "currency:INR" },
    "right": { "col": "usd_price", "type": "currency:USD" }
  }
}
```

**When:** arithmetic or comparison involves two `currency` columns with different units.

---

### `E_ORDER_COMPARISON_NON_ORDERED`

```json
{
  "code":     "E_ORDER_COMPARISON_NON_ORDERED",
  "step":     0,
  "operator": "filter",
  "message":  "Cannot use 'lt' (less-than) on column 'channel' (categorical). Ordering comparisons require an ordered type.",
  "hint":     "Use 'eq' or 'ne' for categorical columns, or 'in' / 'notIn' for membership tests. Ordering comparisons (lt, lte, gt, gte) are valid for number, currency, percent, date, and datetime columns.",
  "context":  { "predicate": "lt", "col": "channel", "type": "categorical" }
}
```

**When:** `lt`, `lte`, `gt`, or `gte` is applied to a `string`, `boolean`, or `categorical` column without a declared domain order.

## Added in v1.1

### Parse errors

Raised before binding, when the JSON doesn't match the contract schema. `step` is null; `pointer` locates the field.

| Code | When | Hint to the model |
|---|---|---|
| `E_PARSE_INVALID_JSON` | The text is not a JSON document. | Return a single JSON object and nothing else. |
| `E_PARSE_UNKNOWN_VARIANT` | A `kind`, `op`, `type` or `mode` value names no variant. | Use one of the variants the schema lists for this position. |
| `E_PARSE_UNKNOWN_FIELD` | A field that doesn't exist there (e.g. `groupby`; or a `range` or `onDependents` a model tried to write, v1.2). | Lists the allowed fields; `candidates` ranks them. |
| `E_PARSE_MISSING_FIELD` | A required field is absent (numbers included: `limit` without `n`, v1.2), or a variant has no discriminator. | Add the field; the schema marks it required. |
| `E_PARSE_INVALID_VALUE` | A value of the wrong type or outside an enum (e.g. `fn: "median"`). | Lists the allowed values. |

### Plan, column and argument errors

| Code | When | Hint to the model |
|---|---|---|
| `E_DUPLICATE_OUTPUT_COLUMN` | Two columns of an `aggregate` or `project` output share a name, ignoring case (v1.2). | Give every output column a distinct name. |
| `E_INVALID_ARGUMENT` | A structurally valid but unusable argument: empty `in` list, empty `and`/`or`, bucket breaks not ascending, `splitPart` index below 1 or empty separator, a `toText` pattern outside the whitelist, `countDistinct(*)`, `sum(*)`, an empty `project`, `moveColumn` after itself, template rows out of order. | Explains the specific constraint. |
| `E_UNKNOWN_METRIC` | `periodCompare.metric` is not a metric of the source table. | Lists the table's metrics, or says none exist yet (catalog-only environments before M8). |
| `E_COUNTIF_NO_PREDICATE` | A `countIf` measure without `where`. | Add the condition, or use `count`. |
| `E_LIMIT_NOT_POSITIVE` | `limit.n` below 1. (An absent `n` is `E_PARSE_MISSING_FIELD` since v1.2.) | For "top 5", use n = 5. |

### Edit-plan errors

| Code | When | Hint to the model |
|---|---|---|
| `E_EDIT_EMPTY` | `ops` is empty. | Add the operations the request asks for. |
| `E_EDIT_UNKNOWN_COLUMN` | An operation names a column that doesn't exist at that point (including one an earlier operation dropped or renamed). | Lists the current columns, with a closest match. |
| `E_EDIT_COLUMN_COLLISION` | `addColumn.as` already exists, ignoring case. | Pick a new name, or use setColumn. |
| `E_RENAME_COLLISION` | `renameColumn.to` already exists, ignoring case (a case-only rename of the same column is fine). | Pick another name, or drop the existing column first. |
| `E_EDIT_DROPS_EVERY_COLUMN` | The plan would remove the table's last column. | Keep at least one column. |

`E_DROP_HAS_DEPENDENTS` moved to the commit (v1.2): see *Commit errors* below.

### Template-sink errors

| Code | When | Hint to the model |
|---|---|---|
| `E_TEMPLATE_UNKNOWN` | `sink.templateId` is not an imported template (raised while binding). | Lists the imported templates; `candidates` ranks them. |
| `E_TEMPLATE_COLUMN_MISSING` | A writable template column has no output column. | Add a project column with exactly that name; map it to a null literal to leave it empty. |
| `E_TEMPLATE_EXTRA_COLUMN` | The output has a column the template doesn't, or writes a template formula column. | Lists the template columns to fill, in order. |
| `E_TEMPLATE_COLUMN_ORDER` | Same columns, different order. | Gives the template's order. |
| `E_TEMPLATE_TYPE_INCOMPATIBLE` | An output type doesn't suit the template column's number format. | Convert first (e.g. toText), or map another column. |
| `E_TEMPLATE_VALUE_NOT_IN_LIST` | A categorical output can write values outside the template column's validation list. | Map the values with a case expression. |
| `E_TEMPLATE_DYNAMIC_COLUMNS` | A pivot feeds a template. | Replace the pivot with aggregate + project. |

### Warnings

| Code | When |
|---|---|
| `W_OVERWRITES_FORMULAS` | `setColumn` replaces a formula column with fixed values. |
| `W_UNMAPPED_TEMPLATE_COLUMN` | A template column is deliberately left empty (mapped to a null literal). |
| `W_UNTRACEABLE_REFERENCES` | The workbook has INDIRECT/OFFSET/external references and the plan removes columns or rows; the impact list may be incomplete. |

### Changed in v1.1

`E_SORT_CATEGORICAL_UNORDERED` now fires only for a domain marked ordinal whose order isn't declared. Nominal categories (regions, names) sort alphabetically; see ir-spec §2.4 and §5.1.

### Plan errors

| Code | When | Hint to the model |
|---|---|---|
| `E_TOTEXT_OUTSIDE_CONCAT` | `toText` is used other than inside a `concat` or as the whole value of a text-formatted template column. | Output the value itself and let the cell's number format show it; use toText only to build text. |

A date written as a plain string (`"2025-01-01"` without `valueType: "date"`) is text, so comparing it with a date column is `E_TYPE_INCOMPARABLE`; an impossible typed date (`2025-13-01`) is `E_INVALID_ARGUMENT`.

### Commit errors

Raised by `ConsentCheck` when the user commits a checked plan. `pointer` points into the commit request.

| Code | When | What the pane does |
|---|---|---|
| `E_COMMIT_PLAN_MISMATCH` | `planHash` isn't the hash of the plan being committed. | Preview again. |
| `E_SINK_ANCHOR_MISSING` | An `anchor` sink and no `anchor` chosen. | Ask where the result should start. |
| `E_DROP_HAS_DEPENDENTS` | The plan removes columns or rows that something still reads, and `onDependents` is `block`. Names every dependent. | Offer: cancel, or convert them to their current values (`convertToValues`). |

|---|---|
| `W_DEPENDENTS_NEED_CONSENT` | An edit removes a column (or rows named by fixed-row references) that something reads. The plan is valid; the preview names each dependent and the user decides at commit. Not a repair signal: the hint tells the model no change is needed. |

## Repair loop protocol

The repair loop sends the full `Diagnostic[]` array back to the model with the following wrapper:

```json
{
  "attempt":     2,
  "maxAttempts": 2,
  "diagnostics": [...],
  "instruction": "The plan above failed type-checking. Correct every error listed in diagnostics and return a new, complete plan. Do not explain your changes — return only the corrected plan JSON."
}
```

On the second (final) attempt, `attempt === maxAttempts`. If the model's second attempt also fails, the service returns a structured refusal to the client:

```json
{
  "outcome":      "refusal",
  "understood":   "I interpreted your question as: quarterly revenue by region excluding returns.",
  "failureReason": "The plan could not be expressed in Sheaf's type-safe IR after two repair attempts.",
  "lastDiagnostics": [...],
  "suggestion":   "Try rephrasing your question, or check whether the columns it references are in the semantic model."
}
```

The refusal message is the legible surface described in design principle 6: "a tool that admits defeat is more trustworthy than one that guesses."
