# Consolidation fixture: four sources → one booking-import template

Synthetic data, generated by `corpus/tools/generate_consolidation.py`. Edit that script and re-run it rather than editing the files by hand. It is modelled on a real real-estate CRM export: the structure is the same, and every value is invented. The project, "Green Meadows", is fictional.

## The job

Fill `bulk-booking-template.xlsx`, **one row per booking** (30 bookings), from four sources keyed by **Registration No.**:

| Source | Rows | Relation to a booking | Notable |
|---|---|---|---|
| `project-bookings.xlsx` | 30 | **1:1, the master list** | 71 columns; instalment blocks repeat their headers (`AMOUNT`, `CGST`, `SGST`, `TOTAL` ×5); "N/A" text in `Allotment Date` and `Unit No.` for unallotted units; two phone numbers in one cell twice |
| `loan-customers.xlsx` | 8 + a totals row | 0..1 | Only bookings with a sanctioned loan; the last row is a totals row (`Area` = "Total:") |
| `addresses.xlsx` | 29 | 0..1 | The whole address in one cell, with the pincode placed differently each time; one booking missing |
| `payment-receipts.xlsx` | 67 + 3 summary rows | **0..n** | Several receipts per booking; a cancelled receipt, a refund, pending cheques, one receipt for a booking that doesn't exist, summary rows with merged cells at the bottom |

This is **consolidation by key**, not stacking: every template row is one booking, assembled from up to four sources, with the receipts summarised first (first payment, total cleared).

## The same fact in several places must agree

Name, mobile, email, booking date and unit appear in more than one source. After normalising (trim, ignore case, drop a leading Mr./Ms./Mrs./Dr., compare phone digits only), they must be equal. When they aren't, the row is still filled from the master, but the conflicting cells are **highlighted** and listed.

| Registration | What | Where |
|---|---|---|
| 4106 | mobile differs | bookings vs loan file |
| 4112 | booking date differs by 3 days | bookings vs loan file |
| 4126 | name differs ("… Joshi" vs "… Joshi Kapoor") | bookings vs addresses |
| 4119 | **not** a conflict: the same name without its title | bookings vs loan file |
| 4105, 4114 | **not** a conflict: two numbers in one cell, and the first matches | — |

## Everything else that must be caught (`expected.json`)

- **Unmatched:** 4122 has no address; a receipt belongs to 4999, which isn't in the bookings.
- **Not data:** the loan file's totals row and the receipts' three summary rows.
- **Data quality:**
  - 4110's address has no pincode;
  - 4117's PAN is written with spaces;
  - every third booking has no unit allotted yet;
  - one cancelled receipt and one refund.
- **Reconciliation:** the cleared, non-cancelled receipts total `clearedReceiptTotal`, and the per-booking receipt counts are listed.
- **Template capacity:** its dropdowns cover rows 2–501. This fixture fits; a larger run must be flagged.

## Decisions a person must make (Sheaf asks; it doesn't guess)

1. What `Status` should a booking with no allotment get?
2. What `Financing Mode` is a "Pending" loan?
3. Is `Booking Amount` the first payment or the total received?
4. Should a conflict stop the fill, or fill from the master and highlight (the default here)?
